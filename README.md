# WorkBuddy 双版本共存工具

面向 Windows 10/11 x64 的用户级管理器，目标是让 **国内版 WorkBuddy** 与 **国际版 WorkBuddy AI** 在同一台电脑、不同安装目录中共存，并由本工具接管安装、更新、回滚与卸载。

> **当前状态（2026-10-22 00:02，v0.6.10）：扫描即自动登记；安装 / 更新 / 卸载 / 启动全部在管理器内完成；安装后自动创建桌面快捷方式，失败写入 `state/errors/`。**
> **签名策略（0.6.1 起）**：Authenticode 的 `Valid` / `NotSigned` / `Unknown` / 证书换签**都不阻止**安装或更新，只写入诊断；仍然拒绝产品不匹配、归档危险、应用树不完整、版本缺失。
> **更新**：点实例的「更新」→ 打开该产品官网 → 你下载安装包 → 回来选文件 → 管理器校验后**原位替换所选实例**（先备份，失败自动回滚）。
> **卸载**：受管实例走受管事务；已接管实例调用**注册表中与该目录精确匹配的官方卸载器**，并轮询确认目录消失。
> 既有官方安装在扫描后自动登记（只写管理器状态，不动客户端文件），无需任何确认步骤；
> 安装与更新都走**解包部署**（不执行安装器、不传静默参数、不修改安装包）。**安装时可选择最终目录**（任意本地固定磁盘），更新沿用实例原路径。
> **真实官方包已实测**：国内版 5.8.3 官方包（NSIS 3，内层 `$PLUGINSDIR/app-64.7z`）完整部署成功，完整应用树校验通过。
> **未交付**：官方在线源 API、部署后运行/登录验证、删除用户数据、进程关闭、注册表/开始菜单登记。
> 详见 `docs/FEATURE_GAP.md` 与 `docs/TEST_MATRIX.md` 第六阶段。

### 候选版本（不是支持承诺）

既往记录中出现过 **国内版 5.8.3**、**国际版 5.8.4**，但记录互相不一致，也从未在受控环境中复现。
这两个版本号仅作为**待重新验证的候选版本**保留在 `docs/TEST_MATRIX.md` 中，**不写入代码、不作为允许清单**。
代码中不存在任何硬编码的允许版本；所有版本与发布者都来自证据包。

### 检测状态与写操作授权是两件事

- **检测**不依赖虚拟机证据包：登记、快捷方式、运行进程、常见安装位置、用户指定目录都能发现安装并读出产品名/版本。
- **身份**按可读的 `product.json` / `package.json`（含 `app.asar` 内）判定：`identified`（含 `confidence`：`verified` / `observed`）或 `unverified` / `conflict`。
- **写操作**分两条链路：自动事务仍只由证据门控制（无证据时恒为关闭）；**辅助启动**按「每产品 × 每操作」独立判定，
  且必须有可用发布者基线 + 用户确认，只能启动官方交互式界面。
- 文件名、目录名、卸载显示名、单一元数据字段或进程名只能作为线索，不能单独放行任何写操作。

## 诊断报告（schema v4）

导出诊断会**先重新扫描**，再分别列出：

- `managedInstances`：管理器登记的实例（instances.json）
- `scan.records`：本次扫描在磁盘上发现的安装
- `scanToManaged`：两者按路径关联后的状态（matched / discovered-not-managed / managed-not-found-on-disk / identity-conflict）
- `recentOperations` + `recentErrors` + `lastOperation`：事务 journal 与失败日志按时间合并
- `diagnosticsBuildId` / `diagnosticsSchemaVersion`：确认报告来自当前运行的构建

扫描失败时报告 `scan.status="failed"` 并给出失败码，不会拿旧扫描结果冒充新数据。

## 已实现的能力

- **通用发现（6 个来源）**：卸载登记（HKCU + HKLM 32/64）、登记字段推导、运行中进程可执行路径、桌面/开始菜单快捷方式、
  有界常见安装位置（`%LOCALAPPDATA%\Programs`、`%ProgramFiles%`、`%ProgramFiles(x86)%` 的直接子目录）、用户指定目录。
  同一路径的多条线索合并为一份安装并保留全部线索；同一路径的重复登记合并并标注；路径无法解析时显示“登记已发现，路径待解析”。
- **身份核验**：读取 `resources/app/product.json`、`resources/app/package.json`，以及打包进 `resources/app.asar` 的同名文件
  （`productName` 优先，因为两版的 `name` 相同）；比对产品名、数据目录名、版本；绝不读取登录凭据、令牌、聊天内容。
  注：Electron 会把 `app.asar` 当目录拦截，读取归档必须走 `original-fs`。
- **安装包校验**：SHA-256 + Authenticode 状态 + 发布者 + 包内产品名；任一项无法确认即 `unknown`，不默认通过。
- **预演（dry-run）**：列出每个将读取/创建/替换/备份的精确路径、签名者、哈希、所需空间、回滚步骤；存在阻断项即禁止执行。
- **事务与操作日志**：`planned → staged → verified → committed` 状态机，原子写入；失败自动回滚；崩溃后只允许"继续验证"或"回滚"，不允许猜测状态删除文件。
- **路径守卫**：拒绝磁盘根、系统目录、用户数据目录、UNC 共享、设备命名空间、8.3 短名、重解析点逃逸、`..` 逃逸。
- **发布来源白名单**：只接受已审阅的精确 HTTPS 主机；重定向不跟随；响应 schema 严格解析；体积上限、超时、取消。
- **界面**：单页显示两个产品的发现状态、版本、路径与线索来源；三态（未发现 / 已发现待确认 / 已识别未开放）；
  支持重新扫描与目录补扫；安装/更新/卸载为禁用按钮并说明原因；无官方来源时不显示任何在线版本。
- **脱敏诊断**：导出时替换用户主目录与用户名，丢弃疑似凭据行；路径收敛为"盘符 + 层级 + 末级目录 + 短哈希"。
- **统计口径**：安装份数按去重后的实际目录计；来源区标题为"检测线索"，明确"线索数不等于安装数"；
  同一目录的多进程/多快捷方式/多登记不重复计数。
- **快捷方式降噪**：名称与 WorkBuddy 无关的坏快捷方式只做一行弱化汇总，不再逐条占据跳过项。
- **辅助启动（每产品 × 每操作）**：安装 / 更新 / 卸载各自判定为「可辅助启动 / 仅提供指引 / 已阻止」。
  安装包须通过扩展名、体积、Authenticode、产品身份与发布者基线检查；通过后由用户确认，
  只以 `spawn(文件)` 启动官方交互式界面（不传任何参数），结束后强制复扫并以复扫结果下结论。
  多副本更新、`MsiExec` 托管卸载、卸载程序路径失效等场景一律降级为人工指引。
  **v0.2.0 起不再是主流程**：代码保留为显式 fallback，主界面只提供管理器内的受管部署。
- **受管部署安装**：本地官方包 → 校验（哈希/签名/发布者/产品身份）→ 7za 解包 NSIS/7z/zip →
  递归解析内层 `app-*.7z` → 定位 `resources/app` → 事务复制到 `<管理根>/<产品>/versions/<版本>` →
  部署后核验产品元数据与可执行文件 → 登记受管实例。
- **更新（side-by-side）**：指定实例 → 新版本部署到新目录 → 核验 → 切换默认实例 → 旧版本保留为回滚点；
  任一步失败自动删除新目录并保留旧实例。
- **卸载（受管目录）**：只删除本工具部署的程序目录，删除前自动备份；用户数据目录从不访问。
- **启动**：从受管实例启动主程序，启动前校验签名有效。

## 明确不做

跨平台；企业集中部署；账号迁移或聊天数据复制；绕过产品登录限制；静默提权；服务端托管更新源；修改或重打包官方安装器；自动信任新证书；
**静默/无人值守安装**、**接管客户端内置更新器**、**静默卸载或删除用户数据**、**模拟点击或绕过 UAC**。

## 快速开始（开发）

```bash
npm ci

npm run scan:report   # 只读扫描并输出脱敏 JSON 到 artifacts/（不建窗口、不写目标）

npm run dist:portable # 生成携带版（单 exe + 绿色 zip）到 release-portable/
```

## 打包（携带版）

```powershell
npm run dist:portable    # 构建 → 校验 Electron 运行时 → 写入 release-portable
npm run verify:package   # 单独校验 release-portable\win-unpacked
```

`dist:portable` 不再让 electron-builder 直接写交付目录：先在系统临时目录构建，
校验通过（13 个必需运行时文件 + locales + app.asar + 7za.exe，大小与 Electron 一致）后才覆盖交付目录。
**不要直接运行 electron-builder 输出到 `release-portable`**——构建中断会留下缺 `ffmpeg.dll` 的残缺目录。

## 两种分发形态

| 形态 | 产物 | 数据位置 | 适用场景 |
| --- | --- | --- | --- |
| 安装版（NSIS，per-user） | `workbuddy-dual-edition-manager-<版本>-x64.exe` | `%APPDATA%\workbuddy-dual-edition-manager`、`%LOCALAPPDATA%\WorkBuddyDualEdition` | 日常固定使用，有开始菜单/桌面快捷方式 |
| **携带版（portable）** | `workbuddy-dual-edition-manager-<版本>-x64-portable.exe` | **exe 同级 `WorkBuddyDualEdition-Data\`** | U 盘、临时机器、不想写注册表/AppData |
| 绿色目录版（zip） | `workbuddy-dual-edition-manager-<版本>-x64.zip` | 解压后同 `便携版` 规则 | 内网拷贝、批量分发 |

携带版行为说明：

- 单文件 exe，双击即用，**不安装、不写注册表、不创建快捷方式**。
- 启动时 electron-builder 注入 `PORTABLE_EXECUTABLE_DIR`，主进程把 `userData` / `sessionData` / `cache` / `logs`
  以及设置、操作日志、受管目录全部重定向到 `WorkBuddyDualEdition-Data`，实现"整个文件夹拷走即用"。
- 该目录不可写（例如只读 U 盘）时自动退回默认用户目录，界面"管理根目录"会显示实际使用的路径。
- 标题栏右侧会显示"· 携带版"标识。
- 卸载 = 直接删除 exe 与 `WorkBuddyDualEdition-Data` 目录；不会残留注册表项。

## 安全底线

- 不从非官方镜像获取客户端安装包；不以文件名作为版本身份依据。
- 不删除用户数据；辅助卸载只启动原厂卸载程序，本工具自身不删除任何文件、注册表或快捷方式。
- 更新来源、签名或产品身份无法验证时失败关闭，保留现有可启动版本。
- 自动更新默认关闭；自动下载与自动安装是独立开关，且需要能力门通过。
- 任何需要管理员权限的步骤都必须展示原因、命令与目标，由用户单独确认。
