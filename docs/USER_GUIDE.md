# 使用指南（中文）

> 当前版本 v0.5.0：**打开即自动登记**，没有额外的登记步骤。
> 更新 = 打开官网取包 → 回来选文件 → 原位替换所选实例；卸载 = 受管事务或官方卸载器。
> 安装是把官方安装包解包后部署到版本化目录，**不运行官方安装器、不传静默参数、不修改安装包**；
> 更新采用并排部署（旧版本保留为回滚点）；卸载只删除本工具部署的程序目录，**用户数据默认保留**。

## 1. 安装管理器

### 1.1 安装版（NSIS）

1. 双击 `workbuddy-dual-edition-manager-<版本>-x64.exe`。
2. 为**当前用户**安装，不需要管理员权限；可选择安装目录。
3. 目标机器**不需要**预装 Node.js；解包组件 `7za.exe` 随包分发。

### 1.2 携带版（免安装）

1. 把 `workbuddy-dual-edition-manager-<版本>-x64-portable.exe` 复制到任意可写目录（U 盘也可以）。
2. 双击运行，**不需要安装**，不写注册表、不创建快捷方式、不写 `%APPDATA%`。
3. 首次运行会在 exe 同级创建 `WorkBuddyDualEdition-Data\`：
   - `app\`：Electron 缓存与用户设置
   - `state\`：设置、实例注册表 `instances.json`、发布者信任 `signer-trust.json`
   - `Managed\`：受管安装目录与备份
4. 换机器时把 exe 与该目录一起拷走即可保留配置与已部署实例。

### 1.3 绿色目录版（zip）

解压后运行目录内的 `WorkBuddy Dual Edition Manager.exe`，数据落点与携带版一致。

## 2. 主界面

一页两栏，国内版与国际版各一张卡片。每张卡片直接列出**检测到的安装**：

```
国内版 WorkBuddy   已发现 2 个实例
  E://Programs//workbuddy        5.8.3  [官方安装]
    发布者：CN=Tencent Technology (Shenzhen) Company Limited
  
  E://WorkBuddy-CN               5.8.3  [官方安装]
  
  ─────────────────────────────────
  [安装新版本…]  从本地官方安装包部署到独立目录，不影响其它安装
```

状态只有两种，含义直白：

| 卡片状态 | 含义 | 你能做什么 |
| --- | --- | --- |
| 未安装 | 没有发现任何实例 | 点「安装新版本…」 |
| 已发现 N 个实例 | 已自动登记，可直接操作 | 启动 / 更新 / 卸载 |

- **诊断**在工具栏按钮里（弹窗），首屏不显示线索计数、跳过项、候选与补扫目录。
- 顶部不再常驻「官方在线来源未配置」；来源只在安装流程里说明。

## 3. 自动登记（无需操作）

打开管理器或点「重新扫描」后，凡是**身份、路径、主程序、签名**都通过校验的安装，会自动登记为可管理实例：

| 条件 | 说明 |
| --- | --- |
| 产品身份已确认 | 元数据（productName/applicationName）与产品匹配 |
| 安装目录存在 | 且不是符号链接 / junction |
| 主程序存在 | 自动排除 `Uninstall*.exe`、`RepairApp.exe` 等维护程序 |
| 主程序签名有效 | Authenticode 为 Valid |

登记只写管理器自己的状态文件，**不移动、不覆盖、不删除、不启动客户端，不碰注册表/快捷方式/用户数据**。
同一目录重复扫描不会重复登记；多副本按真实路径分别列出。

没有通过校验的记录会以「无法管理」+ 一句原因显示（例如「主程序签名状态为 未知」），不提供任何操作按钮。

## 4. 安装

解包组件已随管理器提供，无需另装 7-Zip。官方包解压后约 1.1 GB，请确保目标盘有约 2.4 GB 可用空间。

1. 点产品卡片下方的「安装新版本…」。
2. 选择本地官方安装包（`.exe` / `.7z` / `.zip`）。
3. 弹窗显示：包路径、版本、包内产品名、签名状态与发布者、SHA-256。
4. **确认最终安装目录**：输入框可直接编辑，或点「浏览…」选父目录后自动拼上产品目录名（如 `WorkBuddy-CN`）。
   默认值只是推荐路径；目录可以不存在（由管理器创建），已存在时必须为空。
5. 确认后管理器执行：解包 → 定位应用 → 部署到**你确认的目录** → 核验元数据与可执行文件 → 登记实例 → 创建桌面快捷方式。
6. 成功后实例出现在卡片里并成为默认实例；失败会自动清理，不留半成品目录。

**签名与发布者（0.6.1 起）**：管理器不因为签名状态替你做决定。`Valid`、`NotSigned`、`Unknown`
或证书换签都不会阻止安装/更新，签名结果只写入诊断。仍然会拒绝：包内产品与所选产品不一致、
归档结构危险（路径穿越/链接）、缺主程序或应用代码、版本无法识别、磁盘不足、目标目录被占用。

**安装完成后会自动创建桌面快捷方式**：`WorkBuddy（国内版）.lnk` / `WorkBuddy AI（国际版）.lnk`，
目标指向该实例目录内的主程序。快捷方式创建失败不会回滚安装，结果里会写明原因。

## 5. 更新

1. 在目标实例上点「更新」。
2. 确认框会说明：下一步打开该产品官网（国内版 `workbuddy.cn` / 国际版 `workbuddy.ai`），你在官网下载 Windows 安装包。
3. 点「打开官网并选择安装包」：浏览器打开官网，同时弹出文件选择框。
4. 下载完成后在文件选择框里选中该安装包（取消则不会写入任何文件）。
5. 管理器校验：产品身份、Authenticode 签名、发布者指纹、版本必须高于当前版本。
6. 二次确认后执行：**完整备份现有目录** → 解包新版本 → 同卷目录替换 → 校验 → 失败自动回滚。
7. 更新的是你点的那一个实例目录；旧版本目录保留（`<目录>.old-<操作号>`），备份在 `<管理根>/<产品>/backups`。

不会发生的事：不后台自动下载、不猜下载直链、不跑官方安装器、不强杀运行中的客户端（会提示你先退出）。

## 6. 卸载

两种实例走两条不同路径，界面文案也不同：

| 实例类型 | 卸载方式 | 说明 |
| --- | --- | --- |
| 本工具部署（标记「本工具部署」） | 受管事务 | 先备份程序目录，再删除；用户数据不动 |
| 官方安装（标记「官方安装」） | **官方卸载器** | 从注册表找与该目录精确匹配的 `UninstallString`，校验签名与产品后启动，并轮询确认目录消失 |

官方卸载器的命令行会被结构化解析：只放行 `/currentuser`、`/allusers` 这类作用域参数，其他参数（含静默 `/S`）一律拒绝。
官方卸载器可能有它自己的确认步骤，请按提示完成。若卸载器退出但目录仍在，界面会报失败并保留跟踪记录。

若官方卸载器不可用（注册表无匹配登记），界面会明确报错并保留登记，不会退化成删目录。

## 6.1 快捷方式与失败日志

- 安装成功后自动创建对应产品的桌面快捷方式；更新后指向同一个实例目录，不会重复创建。
- 卸载时只删除**本工具创建**的快捷方式，你自己在桌面建的快捷方式不会被删除。
- 任何安装 / 更新 / 卸载失败都会写入 `WorkBuddyDualEdition-Data/state/errors/<时间>-<操作>.json`，
  记录阶段、错误码、是否回滚和真实错误消息；内容已脱敏，不含用户名、完整路径、令牌或命令行。
- 携带版的日志就在 exe 同级数据目录里，方便直接取给客服排查。

## 7. 启动

点实例上的「启动」，管理器从该实例目录拉起主程序；启动前校验签名有效，签名无效时拒绝启动。

## 8. 诊断与扫描

- 工具栏「诊断」按钮打开弹窗：检测线索、跳过项、其他候选、补充扫描目录、导出脱敏诊断。
- **重新扫描**：只读扫描六个来源（卸载登记、登记字段推导、运行进程、快捷方式、常见安装位置、补充目录）。
- **补充扫描目录**：只检查该目录下名字含 workbuddy 的直接子目录，不递归整盘。
- **导出脱敏诊断**：JSON 中路径被替换为「盘符 + 层级 + 末级 + 短哈希」，不含用户名、完整个人路径、命令行或凭据。

## 9. 官方在线来源

`config/releases.json` 当前没有任何已核验端点，因此界面显示「官方在线来源尚未配置」，不会发起任何网络请求。
只支持本地官方安装包。补齐经审阅的官方主机与实测 schema 之前，这一状态不会改变。

## 10. 卸载管理器本身

**安装版**：在 Windows「设置 → 应用」中卸载；不会删除 `%APPDATA%\workbuddy-dual-edition-manager`
与 `%LOCALAPPDATA%\WorkBuddyDualEdition`，需要时手动清理。

**携带版 / 绿色版**：关闭后删除 exe 与 `WorkBuddyDualEdition-Data` 目录，无残留。

## 10.1 错误日志与诊断导出位置

- **错误日志**：每次安装/更新/卸载失败都会写一个 JSON，字段含阶段、错误码、脱敏消息、是否回滚。
  - 便携版：`<exe 同级>\WorkBuddyDualEdition-Data\state\errors\`
  - 安装版：`%APPDATA%\workbuddy-dual-edition-manager\state\errors\`（即 `app.getPath("userData")/state/errors`）
- **诊断导出**：点「诊断 → 导出脱敏诊断」后自行选目录，文件名 `workbuddy-diagnostics-<时间戳>.json`。
  报告里 `diagnosticsBuildId` 应与界面标题栏版本来自同一次构建；`schemaVersion` 当前为 4。

## 11. 常见问题

### 提示“该目录已被现有实例占用：D:\”

0.6.10 起不会再出现。旧版本把“运行中进程的可执行文件路径”当成安装目录，当系统返回盘符根
（如 `D:\`）时整块盘都会被判为已占用。现在只有“客户端主程序 .exe 的父目录”才算候选，
盘符根、卸载器、修复器、临时解包目录一律忽略；诊断面板会列为“无效进程路径（已忽略）”。

### 启动报“由于找不到 ffmpeg.dll，无法继续执行代码”

说明拿到的是**残缺的 win-unpacked**（某次构建被中断后留下的目录）。
用 0.6.3 及以后的产物，或运行 `npm run verify:package` 自检；便携版单文件 exe 不受影响。

| 现象 | 说明 |
| --- | --- |
| 卡片显示「已发现 N 个实例」 | 已自动登记，可直接启动/更新/卸载 |
| 出现「无法管理」 | 该行下方有具体原因（签名读不到、缺主程序、身份不一致），该实例不可操作 |
| 安装提示「未通过校验」 | 签名无效、产品名与目标不符、或发布者与已有基线不一致；不会放行 |
| 安装提示「目标目录已存在」 | 同版本目录已存在；更新请用实例上的「更新到新版本」 |
| 安装提示「内置解包组件缺失」 | 管理器文件不完整；重新下载并解压管理器 |
| 更新提示「版本相同」 | 安装包版本与当前实例一致，无需更新 |
| 卸载后用户数据还在 | 设计如此：默认保留用户数据，只有程序目录被删除 |
| 更新时提示「客户端正在运行」 | 先正常退出客户端再重试；管理器不会强杀进程 |
| 更新提示「安装包版本与当前实例相同」 | 需要更高版本；降级要单独处理 |
| 官方卸载器被拒绝执行 | 注册表里没有与该目录匹配的登记，或卸载器签名/产品不匹配；可用「仅移除跟踪」退出管理 |
| 扫描发现两份国内版 | 系统里确实有多个副本；本工具不自动清理，也不把它们纳入受管 |
