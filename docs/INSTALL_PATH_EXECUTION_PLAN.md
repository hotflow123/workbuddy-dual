# 安装目标路径选择补充执行计划

> **交给 WorkBuddy 执行**：项目目录为 `E:\code\workbuddy共存`。本文件是正在执行的 `EXECUTION_PLAN.md` 的独立补充，不要覆盖、重写或打断原计划；先检查 `git status --short` 并保留已有改动。不执行 `npm ci`，不提交、不发布，不对现有客户端做破坏性操作。

**目标：**用户选择本地安装包后，可以明确选择国内版或国际版的实际安装目录；安装到所选路径，完成后自动登记、复扫并创建桌面快捷方式。更新沿用该实例的原目录，不再要求选择新路径。

**现状证据：**`src/renderer/renderer.ts` 的安装流程只调用 `pickPackage()`；没有调用目录选择器。`src/main/services/appService.ts` 在未传 `targetDirectory` 时，将目标自动设为管理根目录下的 `WorkBuddy-CN/versions/<版本>` 或 `WorkBuddy-AI/versions/<版本>`。IPC 虽然接受可选 `targetDirectory`，当前 UI 没有提供它。

**技术栈：**沿用 TypeScript、Electron、现有目录选择 IPC、PathGuard、文件事务、实例登记和 Vitest；不新增依赖。

## 设计决定

- 安装路径由用户明确选择；可预填当前管理根下生成的推荐路径，但不得静默使用默认路径并把它伪装成用户选择。
- 路径输入框显示完整目标路径，提供“浏览”按钮。用户可在输入框输入尚不存在的最终目录；浏览按钮用于选择其父目录，再由用户确认最终目录名。
- 国内版和国际版默认目标目录名称不同，避免撞目录。目标路径可位于 C 盘、D 盘或用户电脑上其他本地盘符，不硬编码 E/F 盘。
- 只允许本地固定磁盘目录。拒绝 UNC/网络路径、磁盘根目录、Windows 系统目录、管理器自身目录、路径穿越、重解析点逃逸和已被其他实例占用的目录。
- 目标目录不存在时由管理器创建；目标已存在且非空时拒绝安装，不能覆盖。若目标已是扫描发现的安装，提示用户使用该实例的“更新”，不创建覆盖式安装。
- 不自动提权。用户选择无写入权限的路径时，显示目标路径和明确的权限错误，让用户自行选择有权限的目录。
- staging 必须位于目标目录同一卷，完成完整树校验后再以事务方式提交；失败回滚并清理 staging。若文件系统不支持原子目录交换，必须有备份/恢复分支，不得假报成功。
- 安装提交后立即写入实例登记并复扫；登记失败时回滚安装，不能产生已安装但管理器不可见的目录。然后创建桌面快捷方式。
- 更新不弹安装路径选择框，固定使用所选实例当前登记路径；更新失败恢复原版本和快捷方式。
